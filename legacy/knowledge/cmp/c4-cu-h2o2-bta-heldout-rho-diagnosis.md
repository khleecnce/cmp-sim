## §1 현황 수치

`tools/completion.py check` C4 실패:
```
C4 (1):  cu_h2o2_bta: 유의 평균 ρ 0.7175 < 0.85
```
`validation/completion_last.json`:
```json
"cu_h2o2_bta": {"n_sig": 1, "rhos": [0.7174500322602797], "n_total": 5, "mean_rho": 0.7175}
```
`n_total: 5` = 이 팩을 참조하는 데이터셋 파일 총수. C4 게이트(`tools/completion.py:333-340`)는
**"유의(p<0.05, 순열검정)한 held-out만 평균"** 한다 — n_sig=1 이므로 평균은 그 한 데이터셋의
ρ 그 자체다. 즉 **0.7175 는 하나의 숫자를 다섯인 것처럼 보여주는 평균이 아니라, 정확히
한 데이터셋의 ρ다.** 그 데이터셋을 찾는 것이 §2의 전부다.

## §2 데이터셋별 ρ·p·n 과 비유의 사유 구분

`pack: cu_h2o2_bta` 를 선언한 5개 데이터셋 전수(직접 `grep` 확인):

| 데이터셋 | n | used_for_calibration | in_scope | ρ | p(순열) | 유의 | 비고 |
|---|---|---|---|---|---|---|---|
| jani2025_cu_h2o2_acidic_chelator | 3 | **true** | true | −1.0 | 1.0 | — | 캘리브레이션 자체라 held 제외 |
| us20080090500a1_cu_ph_silica_cross | 12 | **true** | true | 0.993 | 0.0 | — | 캘리브레이션 자체라 held 제외 |
| lee2021_cu_nicotinic_inhibitor | 3 | false | **false** | 1.0 | 0.1667 | ✗ | in_scope=false(계 밖 표시, 기존 판정) → held 제외 전 단계에서 이미 빠짐 |
| jani2025_cu_rsm_composition_heldout | 13 | false | true | **−0.3494** | 0.877 | ✗ | **순위가 실제로 틀렸다** — n 문제 아님 |
| **tw202115224a_cu_abrasive_size_pressure** | **18** | false | true | **0.7175** | **0.0008** | **✓** | **유일하게 유의한 held-out — 이것이 곧 C4의 0.7175다** |

`held = [not calib and in_scope and rho not nan]`(`validation/backtest.py:346`) 필터를 적용하면
남는 held-out은 **jani2025_cu_rsm(비유의)·tw202115224a(유의)** 둘뿐이다. 이 계산은
직접 엔진을 호출해 재현했다(§6 verify 블록에서 tw202115224a 값 0.7175를 assert로 고정).

**비유의 사유 구분 (지시문이 요구한 절반)**:
- `lee2021`(n=3): p=0.1667 = 정확히 1/6 — 순열검정에서 n=3, 완전일치(ρ=1.0)일 때 나올 수
  있는 **최솟값**이다(3!=6가지 순열 중 1가지만 원순서와 같거나 그보다 좋음). **n이 작아서
  구조적으로 유의해질 수 없다** — 순위가 틀려서가 아니다. (게다가 in_scope=false라 애초에
  C4 집계 밖.)
- `jani2025_cu_rsm`(n=13): p=0.877 — n=13이면 ρ=0.55만 돼도 순열검정으로 유의해진다
  (참고: `us9200180b2_cu_h2o2_series` n=4·ρ=1.0·p=0.0417처럼 n이 작아도 ρ가 높으면 유의해짐).
  **n은 충분한데 ρ 자체가 −0.35로 음수** — 모델이 이 데이터셋에서 **실제로 순위를 뒤집는다.**
  이것은 (b)/(c) 판정 대상이다(§3-2).
- `tw202115224a`(n=18): p=0.0008 — n이 크고 ρ=0.7175 자체가 유의할 만큼 충분히 높다.
  **이 데이터셋은 "유의하지만 완벽하지 않다"** 는 것이 문제이고, 이것이 C4가 요구하는
  0.85 문턱을 못 넘는 직접 원인이다. 아래 §3~§6은 전부 이 데이터셋을 파고든다.

## §3 잔차 조건별 전개

### §3-1 tw202115224a (C4의 실제 원인)

데이터셋 자신의 `notes:`가 이미 정확히 짚고 있다: 변수는 **압력(2.5/1.5 psi)** 과
**연마입자 종류/입경(15~160 nm, 구형·누에고치형·응집체)** 둘인데, 팩에
`abrasive_size_exponent`가 없어(판정#1 null 결과로 의도적 무배선) κ가 입경 항을 적용하지
않는다. 결과: 모델은 **압력 두 값만** 구분해 예측하고(2.5psi→1254.2, 1.5psi→752.5,
전 9배합 동일), 실측은 같은 압력 안에서 310.9~849.3으로 거의 3배 갈린다.

```python verify
import sys, yaml
from pathlib import Path
sys.path.insert(0, ".")
from sim.engine import simulate
import sim.models  # noqa: F401
from validation.backtest import _recipe_from
from scipy.stats import spearmanr

raw = yaml.safe_load(
    Path("validation/datasets/tw202115224a_cu_abrasive_size_pressure.yaml").read_text())
pack = raw["pack"]
conds = raw["conditions"]

obs, pred, shape = [], [], []
for c in conds:
    res = simulate(_recipe_from(c, pack), model="tier2.gw_physical_kp")
    p = float(res.mrr_nm_per_min.mean()) if hasattr(res.mrr_nm_per_min, "mean") \
        else float(res.mrr_nm_per_min)
    obs.append(c["mrr_nm_per_min"])
    pred.append(p)
    s = c["overrides"]["abrasive_size_nm"]
    if s == 50:
        shape.append("cocoon" if "Fuso" in c["label"] else "sph")
    elif s == 125:
        shape.append("cocoon")
    elif s == 140:
        shape.append("agg")
    else:
        shape.append("sph")

# 예측이 압력 두 값으로만 갈린다는 것을 직접 확인 — n=18에 서로 다른 값이 2개뿐
assert len(set(round(p, 1) for p in pred)) == 2

full_rho, full_p = spearmanr(pred, obs)
assert abs(full_rho - 0.7175) < 0.001, full_rho          # C4가 보고한 그 숫자
assert full_p < 0.05

sph_idx = [i for i, s in enumerate(shape) if s == "sph"]
rho_sph, p_sph = spearmanr([pred[i] for i in sph_idx], [obs[i] for i in sph_idx])
assert len(sph_idx) == 12
# 형상을 구형으로 고정한 부분집합만 보면 ρ가 오른다 — 형상이 잔차의 주범이라는 신호
assert rho_sph > full_rho + 0.09, (rho_sph, full_rho)
assert abs(rho_sph - 0.8208) < 0.001

print(f"전체(n=18) ρ={full_rho:.4f}  구형-only(n=12) ρ={rho_sph:.4f}")
```

이 결과가 §4의 "뒤집히는 축"을 정량으로 지목한다: **입자 형상**(구형 vs
누에고치형/응집체)이 같은 압력 안에서 순위를 흔드는 축이고, 형상을 통제(구형만)하면
ρ가 0.7175→0.8208로 오른다 — 그런데도 0.85에는 못 미친다(구형 내부에도 잔차가
남는다, §6).

### §3-2 jani2025_cu_rsm_composition_heldout (비유의 — 참고용, C4 숫자에 미반영)

이 데이터셋은 진단 작성 도중 **별도 작업자(성장엔진)가 독립적으로 조사해 코드를
고쳤다**(커밋 cab964e·b838c89, 판정#72) — 이 진단(#73)이 한 일이 아니지만 전체

인자, [oxalic acid]=+536.63, p=1.7e-7, 팩에 대응 파라미터 없음)를 잔차의 주 원인으로
이미 지목하고 있었고, 판정#72는 여기서 **독립적으로 검증 가능한 별도의 실제 결함**(글리신
착화제 억제 항이 ψ에서 빠져 있던 것, 회귀계수 [glycine]=−440.91, p=4.08e-7)을
발견해 `sim/chemistry.py::_chelator_suppression_term`으로 배선했다

C4 숫자에는 영향이 없다 — 이 데이터셋은 애초에 비유의(p=0.877)라 C4 평균에

글리신 수정 후에도 **−0.3494(비유의)로 남는다**(§2 표에 이미 반영된 수치 = 판정#72
이후 값 — 이 진단이 직접 재실행해 확인했다, §6 verify와 같은 방식).

⚠ `qa_loop.py`의 F4 감사가 이 데이터셋에 경고를 냈다(`chelator_suppression_a`가
같은 문헌 10.1149/2162-8777/adc59e에서 도출 — `used_for_calibration` 누락). 이것은
격리(🔒)가 아니라 경고(⚠)다 — 감사 휴리스틱이 **논문 단위**로만 접촉을 보고 **표/조건
단위**(계수 역산에 쓴 4조건 vs held-out 13조건)를 구분 못 하는 것은 판정#58 §목격과
같은 한계다. 계수 역산에 실제로 쓴 조건은 이미 제외돼 있어(데이터셋 YAML 자체 주석)
순환은 없지만, 정직하게 이 경고를 숨기지 않고 여기 기록한다.

**같은 입경(50 nm), 같은 압력, 형상만 다른 유일한 직접 대조쌍**이 1.915배 차이 난다.

독립적으로 재현**한 것이다(그 노트는 판정#68에서 이미 이 데이터셋을 이 목적으로 분석해뒀다).

## §5 정의역 대조 — 판정#57·#58 패턴 여부

판정#57·#58 패턴("원자료는 정상, 우리 함수형이 정의역 밖")과 **다르다**. 저 두 판정은
캘리브레이션이 커버하지 못하는 **운전점**(농도·pH 범위)으로 외삽한 사례였다. 이 데이터셋은
운전점(압력 1.5~2.5 psi, 실리카 0.08 wt%, H2O2 1 wt%)이 팩 범위 안이고 외삽이 아니다 —
문제는 **입력 자체가 모델에 없는 축**(형상)이라는 점이다. 이는 오히려 판정#68이 이미 이
데이터셋으로 직접 진단한 것과 **완전히 같은 사례**다: 판정#68은 이 축을 "**진짜 물리
효과로 확정했으나(E3, 대상계 실측 + ma15217525 독립 corroboration) 배선하지 않는다**"로
종결했다. 이유는 정의역 문제가 아니라 **자기채점 회피**다 — 정밀 배수(1.395배)의 유일한
출처가 바로 이 held-out 데이터셋 자신이라, 팩에 박으면 C4가 검증하려는 그 데이터로
C4를 통과시키는 순환이 된다(과제 지시 §절대금지 "ρ를 목표로 값을 고르는 것"과 동형).

## §6 축 부분집합 재계산

§3-1 verify 블록이 이미 수치로 보여줬다:
- 전체(n=18): ρ=0.7175
- 형상=구형만(n=12): ρ=0.8208 (+0.1033)

형상을 통제하면 ρ가 오르지만 **0.85는 여전히 못 넘는다** — 구형 내부에도 압력 두 값
으로 묶이는 tie 안에서 5개 배합(15nm×2사·27nm×2사·50nm×1사·160nm)의 실측이 완전히
단조는 아니기 때문이다(예: 2.5psi에서 15nm 620.4/549.2 > 27nm 514.0/562.9 > 50nm 441.4,
그런데 160nm=775.7로 다시 튐 — 입경 자체는 판정#1·판정#68 모두 이 구형 부분집합에서
비유의(ρ=0.087, p=0.787)로 이미 null 처리됨). 즉 구형 내부의 잔여 잡음은 **다른 축이
아니라 개별 배합(제조사·정확한 D50 측정치 편차 등) 수준의 잡음**으로 보이며, 추가로
분리 가능한 구조적 축은 발견되지 않았다 — 형상이 지배 축이고, 그 다음은 잡음 바닥이다.

## §7 판정 — **(c) 구조적 한계, 코드·YAML 미변경**

**C4 `cu_h2o2_bta` 실패의 유일한 직접 원인(tw202115224a, ρ=0.7175)은 판정#68에서 이미
확정·종결된 입자 형상(κ) 축 문제다.** 형상 효과는 (a)처럼 "실체가 있고 고칠 수 있는
결함"이지만, **고칠 수 없는 이유가 물리적 근거 부족이 아니라 자기채점 회피 규칙**이다 —
정밀 배수의 유일한 출처가 바로 이 held-out 데이터라서, 지금 배선하면 이 진단 과제
자체가 금지한 짓("ρ를 올리려고 held-out에서 역산한 계수를 박는다")이 된다. 독립
문헌(ma15217525, 세리아/유리계)은 방향만 주고 배수를 안 준다(판정#68 §3). 원 논쟁의
당사자 논문(Kim et al. 2021, Powder Technology, DOI 10.1016/j.powtec.2020.11.058)은
이번 회차도 확인 결과 여전히 미확보(OpenAlex/Unpaywall/S2 전부 closed, sci-hub 3미러
캡차, 판정#68 §1 그대로 — `tools/find_open_access.py --title` 을 이번에도 새로 돌리지
않았다, 판정#68이 같은 날 이미 5경로를 소진해 재시도는 중복이다).

**분리해서: jani2025_cu_rsm(비유의, C4 숫자에 미반영)은 별개 사례로, 별도 작업자가
이미 적용한 (a)형 수정(판정#72, 글리신 억제)이 있고 여전히 남은 잔차는 옥살산
미모델링(b, 문헌 자신이 지목한 축)이다 — 이것도 코드는 건드리지 않는다(옥살산
폐형식을 도출할 1차 근거를 이번 회차에 새로 확보하지 못했다).**

결론: **격자 숫자를 움직이지 않는다. C4는 예상대로 실패 상태를 유지한다** — 이것이
정직한 결과다. 이 진단(#73)은 코드를 한 글자도 바꾸지 않았다 — 이 회차에 있었던
유일한 코드 변경(글리신 억제항, 판정#72)은 다른 작업자의 독립적 결과물이며, C4
