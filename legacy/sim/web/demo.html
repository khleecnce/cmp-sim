FabSim

A physics-and-chemistry CMP (chemical–mechanical planarization) process simulator, built and validated against published data only. Personal project · private demo.
Open 3D Simulator → Model basis report Factor API (JSON)

What it does

Given a slurry / pad / conditioner-disk / tool recipe, FabSim predicts removal rate across the wafer radius, within-wafer non-uniformity, pad temperature, friction, endpoint time through a multi-layer film stack, and scratch risk — and shows where every number came from. The 3D view models a full 300 mm polisher (load ports → 3 platens → cleaner) down to the pad grooves and slurry film; recipe changes drive the physics and the scene together.

Engineering discipline

  • No number without a source. Every parameter carries value / unit / source / confidence. A missing parameter raises ParamMissing — there are no silent defaults. Enforced in CI.
  • Held-out validation. Datasets used to fit a parameter are flagged used_for_calibration and excluded from scoring. Significance is a permutation test, not raw ρ (n = 3 with ρ = 1.0 is p = 0.17 and does not count).
  • Regression gate. Every model change re-runs all datasets; any significant dataset losing > 0.05 ρ or losing significance blocks the commit. The gate has already rejected one plausible-looking model (a D−1.5 particle-size term: p 0.0007 → 0.76).
  • Fake-data audit. Digitized datasets are cross-checked against source full text (patent tables, PMC XML); arithmetic sequences, self-scoring against the calibration source, and “too-perfect” digitizations are quarantined.
  • Traceable basis. The model basis report is generated from code docstrings and parameter files — it cannot drift from what actually runs.

Honest limits

Rank-order, not absolute. Each material system's Preston constant is back-solved from a single literature point, so absolute MRR can be off by large factors when the recipe leaves that regime (e.g. silica slurry calibrated at pH 11, evaluated at pH 4.7: ~40×). The simulator is for comparing recipes and understanding sensitivities. Absolute calibration requires the user's own measurements, which the Data tab ingests (≥ 3 runs → Kp correction; the physics shape is never touched).
  • Cleaning station is visualization only — no cleaning physics.
  • Particle shape (spherical / cocoon / aggregated) and D10/D90 are recorded, not modeled — no quantitative literature model found.
  • Carrier motor current needs a motor torque constant that is not public; torque is computed, current is not.
  • 12 of 50 factor × material cells still carry estimated rather than literature confidence — the model exists but a primary source for the parameter value has not been located.
